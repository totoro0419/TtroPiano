# 06 — 受け入れ・品質検証計画 / QA

**注意:** 下記は受け入れ計画。実行した試験の結果と証拠は [10_VALIDATION.md](10_VALIDATION.md)。この表の存在だけでPASSにはしない。

## 1. ユーザビリティ（初見テスト）

- 予備説明なしで4小節のメロディーを入力・再生・修正できるか。
- 新しい音を加えたいとき、まず自然な場所を触るか。
- 音符を削除・移動・伸縮したいとき、どこを触ればよいか理解できるか。
- 使わない機能が画面を塞いでいないか。
- 音符長の短い部分でも同じ操作意図が成立するか。
- 同じ機能に複数の入口があることが、混乱より利便性を高めるか。

### 指標と比較

「タップ削除」と「タップ選択＋削除」を、同一課題・類似条件の対象ユーザー群で比較。測定: 完了時間、誤削除、誤移動、Undo数、操作の迷い、主観的な分かりやすさ。どちらが優れているかは**実測で判断**。

## 3. 性能試験

**暫定目標値であって達成済みではない。** まず実機のベースラインを取得し、ユーザー体験と端末性能の結果に応じて調整する。

| 指標 | 目標案 | 計測方法 |
|---|---|---|
| タッチ→視覚フィードバック | P95 ≤ 50ms（通常負荷） | 入力タイムスタンプと描画フレーム |
| ノートを押す→試聴発音 | P95 ≤ 100ms（実機で最終調整） | 録音／オーディオループバック等 |
| パン／ズーム表示更新 | 60fpsを目指す、負荷下でも操作不能にしない | Performance timeline／実機動画 |
| 曲再生の発音位置 | 可聴の不規則な乱れを起こさない | オーディオクロックとの偏差測定 |
| 自動保存 | 編集継続中にも破損・古い上書きを起こさない | 負荷／クラッシュ挿入テスト |
| 大きめの譜面 | 3,000・10,000ノートを比較 | メモリ、FPS、ヒット判定、初回表示 |

端末、OS、ブラウザ、バッテリー設定、音声出力先、作品サイズを測定レポートへ必ず付ける。Bluetoothの総音声遅延は端末依存として分離評価する。
