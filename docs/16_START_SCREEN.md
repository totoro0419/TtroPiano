# 16 — スタート画面とインストール

2026-10-25 JST。「メニュー画面から始めたい」「インストールボタンをさりげなく」の指示に対応。PR #3の最新 `51f1c73ad49162423c44a09e9ae97ad56eadc00b` から分岐し、既存の編集・作品管理・PWAを引き継ぐ。

## 変更

- 通常起動・再読込は必ずスタート画面。新しい曲、つづきから、作品一覧、ファイル読み込み、作例、最近の3作品を表示する。これは通常のページであり、起動時にポップオーバーを開く実装ではない。
- 右上に控えめなインストールボタン。勝手にダイアログを出さない。インストールイベントが使えるときは押下から呼び出し、使えなければAndroid/Chrome/Edge・iPhone/iPadの追加手順を案内する。
- standalone起動またはインストール完了イベントの後はボタンを隠し「アプリとして利用中」を表示。ボタンのテストイベントをOSインストール成功とは扱わない。
- 編集画面のブランドボタン、または「メニュー → スタート画面」で戻る。通常のブラウザーの戻る/進むでも画面を切り替えられる。
- ホーム上でSpaceなどを押しても、背後の再生・編集を起動しない。編集面はinertとaria-hiddenで入力/アクセシビリティの対象から外す。
- 編集面のDOM・Canvas・作品・選択・Undo/Redo・視点・保留中の変更は保持する。ホームは不透明な通常のページとして重ね、キャンバスの再生成やフェードを追加しない。
- 初回にスタート画面を見るだけで空作品を保存しない。新規開始を選んだ時点で作品を有効化する。前回の作品は読み込むが、自動で編集画面へ移動しない。

以前の「起動直後から編集」の仕様は、今回の明示指示により変更。再開はスタート画面から1回押す。作曲15シナリオの既存比較は編集画面に入った後の操作比較であり、この新しい起動操作を含む比較ではない。

UI品質の適用：`NAV.03`（主要な行き先）、`DATA.01/06`（編集を維持）、`STATE.01`（準備/失敗/完了の区別）、`FOCUS.01/05`、`VERIFY.02/06/08`。ホーム上は普通のbuttonとmainを使用し、ARIA menuの矢印操作は既存のコマンドメニューだけに限定する。
