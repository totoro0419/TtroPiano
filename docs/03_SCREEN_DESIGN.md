# 03 — 画面設計 / Tablet-first UI

> 2026-10-25の操作改善により一部の記述を更新。[現行の操作と変更理由](11_DIRECT_COMPOSITION.md)、[最新の比較・検証](12_DIRECT_VALIDATION.md)を優先する。以下は初回設計／実装時の記録として保持。

## 1. 画面コンセプト

**1枚の作曲空間 + 最小限の固定領域 + 状況に応じて現れる機能**。

```text
┌────────────────────────────────────────────────────────────┐
│ ←作品      Undo    Redo        ▶ / ■     120 BPM   ⚙  保存 │ 小さな固定ヘッダー
├────────────────────────────────────────────────────────────┤
│ 1       2       3       4       5       6       7         │ 全曲ミニマップ・タイムライン
├───────┬────────────────────────────────────────────────────┤
│       │ ┆           ┆           ┆           ┆            │
│ 鍵盤  │      ███      █████                        ███    │
│       │ ┆    ███    ┆     ██   ┆ █████       ┆            │ 音符を直接操作
│       │         █████        ███      ███                 │
│       │ ┆           ┆           ┆           ┆            │
│       │              ██████       ██████                  │
└───────┴────────────────────────────────────────────────────┘
│ 強弱 ・ ペダル ・ フレーズ [引き上げて展開]              │ 必要時のみ表示
└────────────────────────────────────────────────────────────┘
```

概念図であり、見た目や寸法は最終デザインではない。アクセシビリティのために可視ラベル／ツールチップも用意する。

## 2. 画面の領域

| 領域 | 常時表示 | 役割 | 最も避けること |
|---|---|---|---|
| ヘッダー | 基本 | 作品名、Undo/Redo、再生、テンポ、設定 | アイコンの増殖 |
| 全体バー／拍目盛り | 基本 | 現在位置、全体への移動、ループ境界 | ノート編集と競合 |
| 鍵盤 | 表示切替可 | 鍵盤の試聴、音名の手がかり | 編集面を過度に狭くする |
| ピアノロール | 最大 | ノート追加・編集・パン・ズーム | 操作ごとにモード切替 |
| 下部シート | 通常は縮小 | 強弱・ペダル・フレーズ・声部 | 普段から高さを占有する |
| コンテキストパネル | 選択時のみ | 対象固有のアクション | 指とノートを覆う |

## 3. 画面状態（最小）

- **通常:** 大きな編集領域。音符追加／削除／移動。
- **選択中:** 選択したノート／フレーズの輪郭、周辺の小さなアクション群を表示。閉じる方法は×、範囲外タップ、同操作の再実行等（ただし空白タップの「音符追加」と競合しない領域に限定）。
- **演奏表現編集:** 下部シートを展開して対象範囲のベロシティ／ペダルを編集。音符本体は上部に維持。
- **ループ再生:** タイムラインにループ境界を表示。編集中の音楽は見える。
- **作品一覧:** 作品サムネ、名前、更新日時、作成、複製、削除、取込み。作曲画面の視点・再生位置を復元。

**設計上の禁止:** 「オーバーレイを閉じるための外側タップ」をノート新規作成と同時実行してはいけない。1操作=意図した1結果。

## 4. ズームと表示規則

- 横方向: 時間、縦方向: 音程で一貫。ピンチ中心の音符／拍位置を極力固定。
- ノートが小さい場合もデータは消さない。短いノート編集には拡大ハンドル／拡大ルーペを表示。
- 拡大率で自動的に「フレーズモード」に切り替えない。フレーズ操作は明示選択。
- ミニマップの再生範囲と編集視点は独立して移動可能。
- グリッド、鍵盤色、音符群の色は視認性を重視。声部は色だけでなく境界／ラベルでも区別。
- ノートを押す指がノートを隠すので、音高・時間・長さのプレビューを指から離れた位置に表示。

## 5. レスポンシブ

- 横向きタブレットを優先設計。縦画面では鍵盤幅・下部シートを縮小し、同じ主要操作を維持。
- PCではホイール／ショートカットを補助的に受け付ける。タッチ優先の原則は変えない。
- 狭い画面で無理にツールを並べず、再生とUndoを最上位の優先順位とする。

## 6. 音色／強弱／ペダルへの導線

音色切替は作品設定内。普段の編集に音色一覧を常設しない。強弱・ペダルは下部の1枚のシートでタブ切替し、ノートの背後にフルスクリーンのダイアログを重ねない。左手／右手の指定は声部情報として選べるが、通常の音符追加では必須にしない。

## 7. 視覚的品質・アクセシビリティ

- アクション状態に明確な押下フィードバックを返す。
- アイコンだけで意味が不明な機能には短いラベルを付ける。
- コントラスト、色覚差、縮小表示を考慮。音程や選択状態を色だけで伝えない。
- ミスをしたとき大きな確認ダイアログで遮るのでなく、Undoと明瞭な状態表示で回復する。
- 重要な変更（作品削除など）は確認付きで行い、ノート削除とは区別する。

## 8. 先に検証する画面上のリスク

(1) タイムラインが狭く再生位置を誤指定する、(2) 密集ノートでタップ削除が多発する、(3) 右端ハンドルが短音符で掴めない、(4) 下部パネルが出るたび視点が飛ぶ、(5) 2本指操作で選択が壊れる、(6) 縦画面で編集スペースがなくなる。結果に応じてレイアウトを調整する。
