# TtroPiano

**タブレットを中心に、ピアノ曲を「考えたとおりに」作れる作曲アプリ。**

> Status: **v0.2 公開プレビュー (2026-10-25 JST)**。音符編集→ピアノ再生→自動保存→MIDI入出力まで接続。操作改善は [変更内容](docs/11_DIRECT_COMPOSITION.md) と [前後検証](docs/12_DIRECT_VALIDATION.md)。初回実装の証拠は [検証記録](docs/10_VALIDATION.md)。Android/iPad実機・初見の使いやすさ評価は未確認。

## 目的

従来のDAWを小さく作り直すのではなく、**音を思いつく → 置く／弾く → 直す → 聴く → 比較する → 曲としてまとめる**という行動を、可能な限り短く直感的な操作に変える。ピアノに絞り、タブレットのタッチ操作を第一級の入力とする。

### 絶対に守る原則

1. **作曲が先、道具は後** — 毎回のツール・モード選択を要求しない。
2. **直接操作** — 音符、和音、フレーズ、再生範囲を触って操作する。
3. **同じ操作は同じ意味** — 覚えにくい隠しジェスチャーを増やさない。
4. **画面を奪わない** — 編集空間が中心。補助UIは必要になったときだけ現れる。
5. **勝手に書き換えない** — 自動補正は明示的／取り消し可能、提案と確定を区別する。
6. **不中断** — 再生中・音符更新中でもパン／ズームなどの操作を受け付ける。
7. **安全性と復元性** — 意図しない削除はUndoで復元。保存の不整合を起こさない。
8. **最初は単純、そのまま高度に** — 初心者版／上級版で操作規則を分断しない。

## 起動・ビルド

Node.js 24で検証。外部の音源/CDNを設定せず起動できる。

```sh
npm ci
npm run dev
```

```sh
npm test       # モデル・履歴・テンポ・ペダル・MIDI往復
npm run check  # TypeScript
npm run build  # 音源hash検証、型確認、本番dist、オフラインキャッシュ
npm run preview
```

CIでは `npx playwright install --with-deps chromium` → `node scripts/prepare-ux-baseline.mjs` → `node scripts/prepare-shell-baseline.mjs` → `npm run test:browser` で本番ブラウザー試験も実行する。作曲操作はPR #1、画面切り替えは初回公開版を固定して比較する。

`/qa/` はブラウザー統合試験画面。「検証を実行」で合成タッチ、実サンプル出力、Worker保存、MIDI往復、10,000音を確認しJSONを取得できる。テスト用作品だけを生成・除去する。再実行時はページを再読込する。

ピアノ音源は同梱済み。元の86MBのSF3は不要。再生成する場合だけPython 3/FFmpegと提供SF3を用い、`python3 scripts/extract-piano.py /path/to/MuseScore_General_Full.sf3` を実行する。権利表示は [音源ライセンス](public/piano/LICENSE.txt)。

## 最初の曲

1. 起動時のスタート画面で「新しい曲をつくる」。前回の曲は「つづきから」で再開する。
2. 空白をタップして音を置き、つかんで動かす。右端で長さを調整。
3. ▶で聴く。下部の声部を「伴奏」にすると左手の音も同じ画面に置ける。
4. 複数音は時間目盛りを横にドラッグして選ぶ。下の「聴く」で試聴、「複製」で続ける。「ループ」でその部分を繰り返す。
5. 自動保存の表示を確認し、次回は同じ場所から再開。「曲の設定」からMIDIまたは完全な作品ファイルを出力。

置いた音・動かした音はそのまま選択される。既存音は「選ぶ」→タップでも選べる。短い音符は左の丸で移動、右の丸で伸縮。「詳細」は必要なときだけ開く。長押しの既存経路も使える。「曲の設定→作例を開く」で4小節の曲も試せる。

左上の「メニュー」には作品一覧・新しい曲・ファイル入出力・設定・ホーム画面追加・操作のヒントをまとめた。作品一覧では名前検索と並び替えができ、「編集中」の作品を確認できる。改名や複製で一覧を閉じ直す必要はない。

スタート画面の右上に小さな「インストール」ボタンがある。対応ブラウザーでは明示的に押したときだけ追加画面を開き、それ以外は手順を案内する。編集画面からは「メニュー → スタート画面」で戻れる。

## 配布

PWAとしてホーム画面へ追加できる構成です。「曲の設定 → ホーム画面に追加」から、対応ブラウザーの追加画面または手順を開けます。初回は接続し、「オフライン準備完了」を確認すると音符編集・保存・ピアノ再生をオフラインで使えます。実機のインストール完了は未確認。

静的Webアプリ。`dist/` をHTTPSの静的ホストへ配信できる。GitHub Actionsにテスト/ビルド、成果物、Pages用ワークフローを収録。

GitHub Pagesの現在の配信元は `gh-pages` ブランチのルート（**Settings → Pages → Deploy from a branch → gh-pages → /(root)**）。2026-10-25の最新スタート画面版を配信したワークフローは [成功](https://github.com/totoro0419/TtroPiano/actions/runs/40183371251) し、`gh-pages/release.json` は検証済みPR #4のソースSHAを記録している。公開URLでの旧版の基本動作検証と、最新コードのブラウザーCI成功は別の検査であり、最新版の全実機操作を確認したものではない。

## 主な操作

| 動作 | 結果 |
| --- | --- |
| 空白をタップ | 音符を追加 |
| 音符を短くタップ | 音符を削除（確定は指を離したとき、即Undo可能） |
| 音符をドラッグ | 音高／時刻を変更 |
| 音符の右端をドラッグ | 音の長さを変更 |
| 空白をドラッグ | パン（画面移動） |
| 2本指を動かす／開閉 | 音符の上からでもパン／ズーム |
| 音符を長押し | 選択／詳細アクション（従来の入口） |
| 入力・移動・伸縮後 | 編集した音を選択。空白への次のタップも追加 |
| 「選ぶ」→タップ／囲む | 待たずに単音／範囲選択 |
| 時間目盛りを横ドラッグ | 区間内の音符を選択 |
| 空白を長押し→ドラッグ | 範囲選択 |
| 鍵盤を押す | プレビュー発音 |
| 時間目盛りをタップ | 再生位置指定 |

**タップ削除は維持。** 誤削除はUndoで復元できる。実機での誤削除率と初見の使いやすさは未確認。詳細な方式比較は [11](docs/11_DIRECT_COMPOSITION.md)。
