# TtroPiano

**タブレットを中心に、ピアノ曲を「考えたとおりに」作れる作曲アプリ。**

> Status: **v0.2 preview 実装 (2026-10-25 JST)**。音符編集→ピアノ再生→自動保存→MIDI入出力まで接続。ブラウザー統合試験の証拠は [検証記録](docs/10_VALIDATION.md)。Android/iPad実機・初見の使いやすさ評価は未確認。

## 目的

従来のDAWを小さく作り直すのではなく、**音を思いつく → 置く／弾く → 直す → 聴く → 比較する → 曲としてまとめる**という行動を、可能な限り短く直感的な操作に変える。ピアノに絞り、タブレットのタッチ操作を第一級の入力とする。

### 絶対に守る原則

1. **作曲が先、道具は後** — 毎回のツール・モード選択を要求しない。
2. **直接操作** — 音符、和音、フレーズ、再生範囲を触って操作する。
3. **同じ操作は同じ意味** — 覚えにくい隠しジェスチャーを増やさない。
4. **画面を奪わない** — 編集空間が中心。補助UIは必要になったときだけ現れる。
5. **勝手に書き換えない** — 自動補正は明示的／取り消し可能、提案と確定を区別する。
6. **不中断** — 再生中・音符更新中でもパン／ズームなどの操作を受け付ける。
7. **安全性と復元性** — 意図しない削除はUndoで復元。保存の不整合を起こさない。
8. **最初は単純、そのまま高度に** — 初心者版／上級版で操作規則を分断しない。

## 起動・ビルド

Node.js 24で検証。外部の音源/CDNを設定せず起動できる。

```sh
npm ci
npm run dev
```

```sh
npm test       # モデル・履歴・テンポ・ペダル・MIDI往復
npm run check  # TypeScript
npm run build  # 音源hash検証、型確認、本番dist、オフラインキャッシュ
npm run preview
```

CIでは `npx playwright install --with-deps chromium` → `npm run test:browser` で本番ブラウザー試験も実行する。

`/qa/` はブラウザー統合試験画面。「検証を実行」で合成タッチ、実サンプル出力、Worker保存、MIDI往復、10,000音を確認しJSONを取得できる。テスト用作品だけを生成・除去する。再実行時はページを再読込する。

ピアノ音源は同梱済み。元の86MBのSF3は不要。再生成する場合だけPython 3/FFmpegと提供SF3を用い、`python3 scripts/extract-piano.py /path/to/MuseScore_General_Full.sf3` を実行する。権利表示は [音源ライセンス](public/piano/LICENSE.txt)。

## 最初の曲

1. 空白をタップして音を置き、つかんで動かす。右端で長さを調整。
2. ▶で聴く。下部の声部を「伴奏」にすると左手の音も同じ画面に置ける。
3. 複数音は空白の長押しから囲む。選択した状態で「ループ」を押すと、その部分を繰り返す。
4. 自動保存の表示を確認し、次回は同じ場所から再開。「曲の設定」からMIDIまたは完全な作品ファイルを出力。

短い音符を伸ばすには長押しで選んで、外側の丸いハンドルを引く。「曲の設定→作例を開く」で4小節の曲も試せる。

## 配布

静的Webアプリ。`dist/` をHTTPSの静的ホストへ配信できる。GitHub Actionsにテスト/ビルド、成果物、Pages用ワークフローを収録。

GitHub Pagesは作業開始時点では未有効。Pagesを使う場合、リポジトリの **Settings → Pages → Source: GitHub Actions** が必要。PRは自動マージしない。試用ページとPRの実際の公開結果は検証記録に記す。

- [試用ページ（ChatGPTログインが必要）](https://ttropiano-compose.ibukioike2009.chatgpt.site)
- [実装PR #1](https://github.com/totoro0419/TtroPiano/pull/1)
- [本番ブラウザー・オフライン試験の成功記録](https://github.com/totoro0419/TtroPiano/actions/runs/40119548820)

作品は端末内のみ。ブラウザーのサイトデータを削除すると作品も消えるため、長く残す作品は `.ttropiano` ファイルにも書き出せる。音符/声部/別案/演奏表現/視点をまとめて保持する。

## 初期の主要操作案

| 動作 | 結果 |
| --- | --- |
| 空白をタップ | 音符を追加 |
| 音符を短くタップ | 音符を削除（確定は指を離したとき、即Undo可能） |
| 音符をドラッグ | 音高／時刻を変更 |
| 音符の右端をドラッグ | 音の長さを変更 |
| 空白をドラッグ | パン（画面移動） |
| 2本指を動かす／開閉 | 音符の上からでもパン／ズーム |
| 音符を長押し | 選択／詳細アクション |
| 空白を長押し→ドラッグ | 範囲選択 |
| 鍵盤を押す | プレビュー発音 |
| 時間目盛りをタップ | 再生位置指定 |

**注意:** 「タップで削除」は意図的に残した仮仕様だが誤操作の可能性がある。ジェスチャー実験で削除率と操作時間を比較し、必要なら標準動作を変更する。音符を消す前に長押しが必須になる設計は避ける。
